# 1.3.3 Sensory Characteristics

## Learning objectives

Identify instructions that depend on a single sensory cue and rewrite them so people can locate and operate content using additional information. WCAG 2.2 criterion 1.3.3 is Level A. Instructions must not rely solely on characteristics such as shape, size, visual location, orientation, or sound. See the [full criterion](https://www.w3.org/TR/WCAG22/#sensory-characteristics).

## Provide another way to identify the target

“Click the round button on the right” assumes a person can see the shape and spatial position. “Select Continue” identifies the control by its label; an additional location cue may still help sighted users. A sound can supplement a message, but an instruction such as “When you hear the beep, press Submit” needs another way to identify the event, such as a visible and programmatically available status message.

Likewise, “The required fields are red” relies on color alone. Add text or a symbol explained in text and ensure each field's required status is available. Color as the only visual means of conveying information is also covered by 1.4.1. The presence of an additional cue does not by itself ensure that the control has an accessible name or is keyboard operable; check those separately.

Location descriptions are not forbidden. “Select Continue, the button at the bottom of the form” combines a name with location. Ensure the visible label and accessible name agree, and update instructions if the interface changes. Instructions should remain understandable when read aloud, magnified, or presented in a different layout.

## Rewrite an instruction without losing helpful detail

A troubleshooting page says, “Press the circular control at the top right.” A person using magnification may see only a small portion of the screen, and a screen reader user may never hear its shape. If the control is labelled “Restart,” say “Select Restart.” You can add “at the top right” as a supplementary clue. The important distinction is whether a user can identify the target without relying exclusively on the sensory characteristic.

The same principle applies to sound. A payment terminal might make a tone when processing finishes. Pair that tone with a visible status such as “Payment complete” that is also exposed to assistive technology. An instruction can then say “When Payment complete appears, select Done.” Do not rely on the phrase “when the tone sounds” as the only way to understand when to act. Check that the message actually appears, stays available long enough, and can be programmatically determined.

## Color, position and responsive layouts

An instruction like “Correct the fields highlighted in red” may lose meaning for a person who cannot distinguish that color. Add text identifying each error and associate it with the affected field. Color may remain a useful supplementary cue. The separate 1.4.1 criterion addresses color as the only visual means of conveying information, and 3.3.1 addresses identifying errors in text. Meeting one does not automatically establish all of the others.

Position can also change at different screen widths. “Use the menu on the left” may be accurate on a large screen but inaccurate after the menu moves to the top on a narrow one. A clear name or heading makes the instruction resilient to layout changes. If a page has two controls with the same visible name, provide enough context to distinguish them, rather than adding only a spatial description.

## Review and test

Search for terms such as left, right, above, below, red, round, and beep in instructions. Their presence is a prompt for review, not proof of a failure. Ask what a user must perceive to identify the target and whether another cue independently supplies the information. Try reading the instructions without looking at the screen, then test with a screen reader or a classmate using a different presentation.

Avoid replacing every location reference with vague wording such as “click here.” Names must correspond to actual labels and should be kept current when the interface changes. Verify the component is operable and that its accessible name can be determined: those are related requirements, not a substitute for understandable instructions.

## Worked example: a booking confirmation

A booking page has two buttons, “Change date” and “Confirm booking.” Its instructions say “Press the green button to finish.” A screen reader user might hear both button names without receiving the color, while a person with color vision deficiency might not distinguish the buttons. Rewrite the instruction as “Select Confirm booking to finish.” The green styling may remain as an additional cue. Confirm that the visible text and accessible name identify the same control.

A second instruction says “Wait for the chime, then collect your ticket.” Add a visible status that says “Your ticket is ready” when the same event occurs. Ensure the status can be exposed to assistive technology, and change the instruction to refer to that message. If the message is transient, consider whether it remains available long enough and whether a user can review it. These interaction details may involve other criteria as well.

Use the same method for an illustrated map. If instructions say “Choose the large circle,” include a text label such as “North entrance” and a control with that name. Check the label stays associated when the page changes size. The goal is not to remove helpful visual and auditory cues; it is to provide another way to understand the instruction without depending on one cue alone.

## Required lesson activity

Review these instructions: “Click the green circle on the right,” “Wait for the beep,” and “Fix the fields in red.” Rewrite each using a control name or textual status and specify how the interface will expose that information. Test your instructions with a classmate who cannot see the original screen. Submit both versions and explain the additional cues.

## Mini-assessment

1. Is “Select Save, the button at the bottom” necessarily a failure because it mentions location?
2. Why is “press the square button” insufficient when shape is the only identifier?
3. Which related criterion addresses color as the only visual means of conveying information?

**Answer guide:** 1. No; the label identifies the control independently of location. 2. It requires the user to perceive shape to identify the control. 3. 1.4.1 Use of Color.
